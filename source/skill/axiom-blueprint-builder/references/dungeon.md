# ダンジョン設計の知見（Axiom BP）

**確度の凡例**　◎=公式資料/Mojang・Axiom公式で確認　○=信頼できる二次資料/実装コードで確認　△=本プロジェクトでの経験則（ゲーム内未検証）

## 1. 設計の流れ（`scripts/dungeon_kit.py` + `examples/example_dungeon.py`）
1. **深さマップを先に出す**：島の各 (x,z) で掘れる深さを一覧表示し、部屋を置ける範囲（深さ ≥ 部屋底+4 程度）を決める。薄い所に掘ると外へ貫通する。（△）
2. **層の寸法**：空間5高＋床1＋天井1。層と層の間・溶岩/水の下には **岩を3枚以上** 残す（内張り1枚だけで隣の空間と接しない）。（△）
3. **掘る → 内張り(`line`) → 仕掛け → `check_leaks()==0` → `solve()` → `render_map()`** の順。内張りは「掘った空間に隣接する岩を石レンガ1枚に置換」するだけで密閉と見た目が同時に取れる。
4. **接地チェックは掘る前**に行う（掘った空間を「地面なし」と誤判定して岩で埋め戻す事故が起きた）。
5. 攻略可能性は **BFS で必ず検証**：歩行／ジャンプ(隙間1〜2)／ハシゴ／扉は「隣接レバーに到達できたら開く」で不動点まで反復。宝箱に隣接して到達できるかも数える。

## 2. 仕掛け（ブロックだけで成立するもの）
| 仕掛け | 作り方 | 確度 |
|---|---|---|
| 鉄の扉＋レバー | 鉄の扉は赤石動力でのみ開く。**隣接する動力源**（レバー等）で作動。**レバーは扉の両側（行きと帰り）に、床ではなく壁に付ける**（face=wall・目の高さ y+1。側壁が無い側は扉と同じ壁面の扉の隣の壁ブロックに付ける）。`door_levers()` が両側を自動で置き、`check_doors()` が検査する。赤石配線不要。扉は上下2ブロック（lower/upper）。 | ◎扉は隣接動力で作動（Minecraft Wiki "Door"）/ ○レバー隣接の運用は広く使われる／両側・壁付けは実機プレイでの指摘（2026-10） |
| 隠し蓋 | トラップドア `half=top` を床と同じ高さに置く＋その下にハシゴ。**ハシゴの真上に置いて開いたトラップドアはハシゴとして登れる**（Java）。 | ◎（Minecraft Wiki "Ladder"） |
| 棘の穴 | 穴の底に `pointed_dripstone`（thickness=tip, vertical_direction=up）。**スタラグマイトに着地すると落下距離が2倍で計算**される。1ブロック以下の落下では発動しない。浅い穴(3〜4)なら軽傷、10ブロックなら致死級。 | ○（複数資料）|
| 溶岩の渡り | 溶岩は**床面と面一**に置く（床ブロックと同じ y）。溶岩は水平・下方向にしか広がらないので、壁と底で囲めば流れ出ない。飛び石は隙間1マスのジャンプ。おとりにマグマブロック。 | ○ |
| 深淵の橋 | 底に水（3段）→ **水深があれば落下ダメージ0**。落ちても死なず、壁にハシゴで戻れる。 | ◎（Wiki "Water"）|
| 迷路 | セル格子(奇数座標)＋DFS（再帰バックトラック）で壁を抜く。入口と出口の外壁を開ける。出口の扉は `door_levers`（両側に壁レバー）。 | △ |
| ループ近道 | 宝物庫→ハシゴ→序盤の部屋の床蓋、で帰り道を短縮。 | △ |

**水の中に置いてはいけないもの**：レバー・ボタン・感圧板・カーペット・松明・赤石・クモの巣・エンドロッド等は水流で壊れる（◎ Wiki "Water" の「影響を受けるブロック」一覧／レバーは二次資料）。水路の先にレバーを置くなら**乾いた足場**に。
**溶岩×水**：溶岩源に水が触れると黒曜石、流れの溶岩はコブルストーン/石になる（◎）。水と溶岩は隣接させない。

## 3. モブ・スポナー（要注意の仕様）
### 自然スポーン（1.18+, Java）
- オーバーワールドの敵対モブは **ブロック光レベル 0** が必須（◎ Minecraft Wiki "Light"/"Mob spawning"：1.18 で「0〜7」から変更）。ランタン/松明が1つでもあれば湧かない。
- さらに **プレイヤーの周囲24ブロック以内には湧かない**、モブキャップ（敵対70）あり（○ 二次資料複数）。→ **小さなダンジョンの暗い部屋に自然湧きを期待しない**。確実に湧かせたいならスポナー。
- 下付きスラブ・カーペットの上には湧かない（○）。

### スポナー
- ブロック名は `minecraft:spawner`、ブロックエンティティIDは **`minecraft:mob_spawner`**（◎ 1.20系のBE一覧）。
- 1.18+ のNBT形式：`SpawnData:{entity:{id:"minecraft:zombie"}}`、`SpawnPotentials:[{weight:1, data:{entity:{id}, custom_spawn_rules:{...}}}]`（◎ 1.18スナップショット変更履歴 / 旧形式は不可）。
- `custom_spawn_rules.block_light_limit`（単値または min_inclusive/max_inclusive）でブロック光の湧き条件を上書き（◎ Wiki）。ゾンビ/スケルトン/クモ系の天然スポナーは光レベル11まで湧く（○）。
- 数値の意味（◎ Wiki BE一覧）：`RequiredPlayerRange`=作動するプレイヤー距離（球）、`SpawnRange`=水平の湧き半径、`MaxNearbyEntities`、`SpawnCount`、`Min/MaxSpawnDelay`（short）。既定値は MaxNearby 6 / RequiredPlayerRange 16 / SpawnRange 4 / SpawnCount 4 など（○ 二次資料）。
- Java の湧き位置は **9×3×9 の箱**で、**壁で遮られない**ので薄い壁の向こう側（隣室）にも湧きうる（○ Minecraft Wiki Talk:Monster Spawner の検証コメント）。部屋の壁は2枚以上の厚みにするか、隣室を離す。
- 湧き位置は箱の中で「床がソリッド＋頭上に2マス空き」が必要。スポナーを壁に埋め込む／周囲に空きが無いと湧かない。スポナーの周囲を明るくすると止まる（光条件を上書きしない場合）。
- 空のスポナー（SpawnData無し）：既定は豚（私の知識。**今回の調査では一次情報を確認できず**、△）。モブ未設定のまま配置しない／設定は BlockEntities で。
- ボス等のエンティティは BP の `Entities` 欄の書式が未確認 → **/summon コマンド**で召喚（`export_commands`）。

## 4. 宝箱・ルートテーブル
- チェストBE：`{id:"minecraft:chest", LootTable:"minecraft:chests/…", x,y,z}`（◎）。`Items` と `LootTable` は併用しない。
- 1.20.4 で存在を確認済みの `chests/…`：simple_dungeon, jungle_temple, ruined_portal, woodland_mansion, bastion_treasure, end_city_treasure, ancient_city, abandoned_mineshaft, desert_pyramid, stronghold_library, village/village_plains_house ほか（◎ Paper 1.20.4 LootTables / ○ 一覧）。
- 難度配分の目安：序盤=simple_dungeon、中盤=jungle_temple/ruined_portal、終盤=woodland_mansion、宝物庫=bastion_treasure/end_city_treasure/ancient_city。

## 5. 階段・ハシゴ・動線
- 上り階段の長さ = 高さ（1:1）。頭上は **2マス空ける**（床/天井の層を貫通させる）。着地側の内部幅が足りない階は **ハシゴ**（壁か心柱に付ける。`facing` は壁から離れる向き）。
- 螺旋階段：5×5 の外周16マスを1周すると14〜15段下れる。階段 `facing` は「上る側（前のセル）」方向（◎ 階段の facing=ブロックの高い側が向く向き）。
- 暗い通路は**入口・分岐・宝箱の近くだけ**明るく（ランタン）。全部明るくするとスポナー以外の緊張感が消える。（△）
- 鉄の扉は「レバーをONにしている間」開く。一度引けば開いたままだが、**レバーが片側にしか無いと反対側から開けられず帰れない**。必ず両側に付ける。（△）

## 7. 上階ほど狭い立体（ピラミッド等）の設計メモ（△ 本プロジェクトで実装・検証）
- **各階の許容半幅**：階 y の外殻半幅を `half(y)` として、その階の部屋の最上段 y_top で `|x|,|z| ≤ half(y_top) − 3`（内張り1＋岩2）。上階ほど狭いので、**大きい部屋は下階・小さい部屋は上階**、ボス部屋は「必要な広さ ≤ half(top)−3」になる高さに置く。底辺を大きくすると上階の部屋も大きくできる。
- **階段は「外周→中心へ向けて」上る**：外へ向けて上ると外殻にぶつかる。長い直線階段は避け、**3×3 螺旋（`Dungeon.spiral`、8段で1周・敷地3×3）**を使う。上り先の階の床は `y0+n`。段の facing は進む先、着地セルは環の n+1 番目。
- **螺旋を“島”にする**：溶岩の湖の中央に3×3螺旋を載せた島を作り、飛び石(隙間1)で渡らせると、段差の移動と難所が1か所に収まる。上階の床に吹き抜けができるので縁に低い壁(`sandstone_wall`)を置く。
- **入口は外へ開く**：内張りは「掘った空間の隣接セル」に張られるので、外へ出る通路の外側セルは `open_end()` で登録（line/leak判定から除外）。通路が外殻の外へ数ブロック突き出るなら、そのまま玄関ポーチになる。
- **迷路**：`Dungeon.maze(x0,z0,cx,cz,y0,y1, entrance=('S',0), exit_=('E',5), min_path=22)`。入口と出口の辺・セル番号を指定。解の長さが `min_path` 以上になる seed を自動探索。出口の外壁セルに扉（`door_levers` で両側に壁レバー）。
- **滑らかなピラミッド**：各段 y で半幅 h=B+1−y のリングに、辺=階段(facing=内向き)、角=外角階段(`corner_stair`)、内側=砂岩で埋める → 45°の滑らかな面。8段ごとに別素材(赤砂岩階段)の帯でスケール感を出す。外殻の内側は“詰まった塊”なので、ダンジョンは `carve` で彫り出すだけで壁の厚みが確保される。
- **高台（浮島）**：円形ブロブ `v=1−(r/R)²`＋ノイズ、深さ=md·1.1·v^0.62。ピラミッドの角が高台の縁から出ないよう R ≥ 角の距離+6。外殻の外側は小さな砂丘、サボテン(`age`)と枯れ木。
- **検証の勘所**：`solve()` は「全扉が開く／全宝箱に到達／ボス位置・宝物庫・島に到達」を確認。迷路の解の長さと seed も記録。最初の実行で一発合格しなかった時は、`render_map()` の平面図でどの扉・レバーが孤立しているかを見る。

## 9. 動線設計の原則（調査由来。根拠は research_notes.md §D）
1. **錠を先に見せ、鍵は後ろに**：先に鉄の扉を見せ、そのレバーは危険地帯（溶岩・棘・迷路）の向こうに置く。レバーを見つけてから扉を探す順は避ける。
2. **錠と鍵の距離＝難しさ**：序盤は近く、深層ほど遠く。
3. **ループで戻す**：宝や鍵を取った後は、近道（**両側にレバー**の扉）か梯子で入口付近へ戻す。長い一本道の突き当たりに鍵を置いて全部歩いて戻らせない。
4. **枝分かれと隠し近道**：本道から行き止まりの宝箱部屋を枝分かれさせる。隠し蓋などの近道は一度は通る場所に置く。
5. **返答に依存関係を書く**：入口 → 錠（扉）→ 鍵（レバー）→ 宝 の順を短い表で。
6. **機械検査**：`check_leaks()==0`、`check_doors()==[]`、`check_return(start)==[]`、`solve()` で全扉が開き全宝箱に到達。
