# 平面の文様・曼荼羅・魔法陣・レリーフ

地面に敷く文様や、空中に立てる板状のレリーフ。ヘルパーは `scripts/pattern_helpers.py`、例は `examples/magic_circles/`。
**1層で十分な作品が多い**（高さを足すのは頼まれてから。参考画像の立体感は『ブロックの側面の影』が多く、高さは読み取れない）。

## 1. 参考画像（ブロックで作った文様の真上写真）を再現する
`examples/magic_circles/digitize_image.py image.jpg proto.json out.bp --fold ...` が一式。中身の考え方：
1. **1ブロックの幅を測る**：`estimate_block_px`（エッジ列のFFT）。実例は 17.2px（画像 2048px・117×117 ブロック）。幅と高さの推定が近ければ正投影に近い。
2. **中心ブロックと n（奇数）を決める**：左右対称の作品は中心に十字（金ブロック等）があることが多い。前景の外接矩形の中心＝中心ブロック、n = 幅/ブロック幅（奇数に丸める）。
3. **サンプリング**：各セルの中央 9×9px の**中央値**色（縁の滲みと側面の影を避ける）。
4. **代表色(proto)は画像の中の見え方で書く**（ブロックの本来の色ではなく、光と影を含めた値）。画像から数色を実測 → 最近傍で分類。背景色を先頭に。
5. **ゴミ対策**：
   - 暗い影のセルは最濃色へ寄せる（`dark_to`）。
   - 縁のガラス・先端の灰色など**まれな色は出てよい領域を限定**（`--outer` 外周のみ／`--tips` 軸の先端のみ）。限定しないと内側に灰色のゴミが出る。
6. **対称化**：左右上下の鏡像4セルで多数決（`fold_d2`）。同数なら空気以外を優先（細線の欠け対策）。ただし完全な8回対称でない作品（斜めが違う）に D4 を強制しない。
7. **確認**：元画像と並べた比較画像、または `render_top` の上面図を `view`。等角プレビューだけでは崩れに気づきにくい。
8. **ブロックの当て込み**（色→実ブロック）：濃紫=紫コンクリート、Xの質感の紫=紫ウール、青紫=アメジストブロック、灰紫=プルプァ、桃=桜の板材、淡い茶=白のテラコッタ、白=白のウール＋石英、縁の薄色=紫/ピンクの色付きガラス。**推測であることを返答に書く**。

## 2. 色違い（四季・自然色）
`recolor(cls, names, {旧名:新名})`。**形は変えず、濃→淡の並びを保つ**のがコツ（グラデーションの花弁が崩れない）。
- 紫→黄緑（自然色）の例：紫コンクリート→緑コンクリート／紫ウール→苔ブロック／アメジスト→ライムのテラコッタ／プルプァ→スイカ／桜の板材→竹の板材／白テラコッタ→エンドストーン／ガラス→ライム・黄のガラス。
- スイカ・竹・苔は模様が強く、プレビューより派手に見える。気になるブロックは差し替えられると伝える。

## 3. 式で作る（魔法陣・幾何学）
`f(x,z)->ブロック名|None` を書き、`paint(b, f, R)`。**後から書いたものが勝つ**ので、背面→前面の順（外輪→帯→星→飾り→中心を一度クリア→中心の模様→ルーン）。
- 円環：`abs(r-R0)<0.55`（1幅）／`<0.95`（2幅）。鋸歯：`ph=(deg%α)/α; r-r0 < h*(1-abs(2*ph-1))`（交互の色は区画の偶奇）。
- 線：`seg_dist(...)<0.52〜0.85`。**星 {n/m}** は `star_segments`（{12/5} 赤・{12/4} 金を重ねる等）。頂点の飾りは円を `dd<3.6` で3色の同心円に。
- 花弁：`petal_hit(th,r,psi,r0,r1,wmax)` が (t,v,w) を返す → 中心線は `v<0.55`、先端は `t>0.9`、根元〜先端のグラデは `GR[int(t*len(GR))]`（濃→淡）。
- フラワー・オブ・ライフ：`hex_lattice_centers(9, 18.5)` の各中心に半径9の円（`abs(dist-9)<0.62`）、交点を金に。
- 完全な8回対称にしたいなら `f(*fold4(x,z))`。連続関数を直接評価しても D2（左右上下）対称にはなる。
- 光る床：シーランタン/シュルームライト/グロウストーンを星の頂点・中心・円周8か所に（夜も映える）。
- **使わない**：コンクリートパウダー（砂と同じく落ちる）、コンクリートで足りる所に砂。

## 4. ルーン文字
`place_runes(ELDER_FUTHARK, 24, r0, H, su)`＋`rune_hit`。字は『線分（u 0..4, v 0..8）』で定義し、円周上に**連続座標で回転配置 → セルごとに線分距離で塗る**。これでどの角度でも欠けにくい（ピクセルを回すとギザギザで壊れる）。
- 寸法の目安：外側の帯＝高さ 9〜10・幅倍率 1.5〜1.6（字の幅≈6）・太さ `thick=0.85`。内側の帯＝高さ 6〜7・倍率 1.0〜1.2。**高さ7未満は判読できない**。
- 向き：頂部が外向き、時計回りに読む（上の字は上向き、下の字は逆さ＝円形文字の通例）。
- 字形は簡略化（ᛃ ᛈ などは近似）。返答で『近似』と明記する。
- 色：外側は金（画面で映える）、内側は白だと背景次第で薄い。**背景色が明るい環境では内側を濃色に**。
- 区切りは15°ごとの縦線＋菱形、字の中心に点（装飾環）。

## 5. 空中のレリーフ（板状）
`put_relief(b, rx, ry, rz, cell_fn, xr, yr)`。**3層**で立体感：z0=全体、z1=縁より1ブロック内側（縁が段になる）、z2=葉脈・種・中心線（光るブロックで盛り上げる）。
- 向き：南(+z)が表。木の背後 z≈-72 に置くと樹冠の裏に大きく広がる。星や飾りを置くときは範囲を除外する。
- モチーフ：楓5裂 `MAPLE5`（広い葉・広場の床向き）、モミジ7裂 `MOMIJI7`（細く尖る・空中レリーフ向き。`power=1.25, floor=.16`）。`lobed_leaf_r` が外形半径、縁のギザギザは `serration`。
  **失敗談**：最初に半幅 21〜27° / 長さ 11 で作ったら葉が細すぎて楓に見えなかった。5裂なら半幅 31〜36°・長さ 12〜15、床に敷くなら広場半径の 0.8 倍まで大きく。
- ひまわり：外側26枚（黄・中心線橙）＋内側26枚（橙・半周ずらす）＋種の円盤 `phyllotaxis(190)`（黒・4粒に1つ発光）＋茎＋2枚の葉。花弁の半幅 2.5 で隣と根元が自然に融合。
- 葉柄・茎は 2〜3 ブロック幅（1幅は細すぎて浮いて見える）。
- 画像内の円盤が『月』だったものを別のモチーフに差し替える依頼（例:「巨大な丸いレリーフ→モミジ」）では、同じ位置・同じ層構成で関数だけ替える。

## 6. 返答の書き方
サイズ・ブロック数 → 構成（外から内へ）→ 配色（ブロック名）→ 注意点（斜め線は階段状／字形は近似／ブロックの当て込みは推測／ゲーム内未確認）→ 調整案。上面図 PNG を渡すと喜ばれる。
